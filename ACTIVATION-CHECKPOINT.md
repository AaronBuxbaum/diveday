# Offline activation checkpoint

This branch is incomplete and must not be merged or deployed. Production activation has not been requested or performed. It preserves local work and executable regressions for the follow-up.

The working tree enables witnessed sync in normal runtimes, refuses sync protocol 2 while retaining protocol 1 for current snapshot readers, and advances generation on diver merge, actual boat change, trip cancellation/reinstatement, and seat cancellation/restoration/rebooking. The disposable PostgreSQL suite in `/tmp/4787-checkpoint-pg.log` passed eight tests, including gated merge transactions, both boat-change and trip/seat cancellation orders, unchanged and stale retries, and live mark preservation. These tests do not prove all rollout invariants.

Activation remains blocked: (1) after an already accepted offline aboard mark becomes ineligible, the live manifest can silently fall back to an older not-boarded result; the separate uncertainty hold protects seat removal but does not surface a recount in the manifest or headcount. Both domain and security reviewers confirmed this. (2) A later live no-show or turn-away does not advance the seat generation or roll-call frontier, so an older offline mark can reclaim that seat. This is a source audit, not yet a reproducing test. (3) A material dive-mode change can leave the boat ID and generation unchanged; meeting-location changes also do not advance it. (4) Offline crew and checklist observations lack a verified witness and remain for manual review; checklist evidence has no complete local resolution control.

The test suite and E2E snapshot-acquisition assertion were still running or unverified at checkpoint. The stale duplicate test is sequential, not a gated retry/edit race. Preserve the restore cutover stop; never infer identity, causality or replay safety from a client timestamp. Do not open a PR from this branch until the missing user-visible recount and writer boundaries are implemented and verified.

Update: A real PostgreSQL regression reproduced acceptance of an older offline not-boarded mark after a live no-show. The local generation increment makes that case refuse for review; turn-away and no-show undo use the same proposed boundary but are not yet covered by the required concurrency tests. The visible recount, crew/checklist handling, browser run and exact-head CI remain unresolved. This is not a review-ready branch.
