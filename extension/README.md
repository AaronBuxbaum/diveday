# DiveDay certification check (browser extension)

Checks a diver's certification on the agency's own lookup page, from the staffer's own browser, when they press "Check with SSI" on the diver's record, a departure's Divers tab or Today. A PADI card is checked on DiveChek, on the PADI Pros' Site the staffer is signed in to. It also checks a course student's PADI eLearning on the PADI Pros' Site when a staffer presses "Check eLearning with PADI" on a course roster. Both PADI checks are a per-shop switch, off by default, which an owner or manager turns on: Settings, Bookings & waivers, "PADI checks (beta)". With it off a PADI card keeps its "(member sign-in)" link. The seeded demo shop has PADI checks on, so a browser signed in to the real PADI Pros' Site would have the demo's made-up divers typed into real DiveChek: try the demo in a browser that is not signed in to PADI. Decisions: H-105, H-106, H-121. Design: [ADR 20261008-cert-check-extension](../docs/architecture/decisions/20261008-cert-check-extension.md).

The extension decides nothing. It fills in the agency's form, waits for the answer, and hands the page's text to DiveDay, where `src/lib/agency-check.ts` decides whether the card is certified.

## Files

- `manifest.json`: Manifest V3. Host permissions are the agencies' lookup sites only, PADI's two Pros' Site hosts (`pro.padi.com` and `pros.padi.com`) among them; the content script runs only on DiveDay's staff pages, `https://dive.day/shop/*`.
- `protocol.js`: the wire format, the version, and `PAGE_SHAPE_WORDS`, the only words a page-shape report may carry. The app's copies are `src/lib/cert-check-extension.ts` and `src/lib/page-shape.ts`. The app talks only to a copy at or above `MIN_EXTENSION_VERSION` there; an older one gets the agency's link and Settings says to update.
- `agencies.js`: the lookup page for each agency, which must match `src/lib/agency-verification.ts`, and the eLearning page for each agency it reads (`ELEARNING`, PADI only). PADI opens on `pro.padi.com`, where PADI's own pages send pros, and `origins` lists both PADI hosts, so a tab sent from one to the other is still the signed-in site.
- `fill.js`: finds each box by its name, label or placeholder and the button that sends them, and types nothing until all are found. On a page behind the shop's sign-in (`signIn` in `agencies.js`, PADI) it fills only boxes that search (a search box or landmark, the box's own words, or a form's search button when the form holds no box the lookup does not fill), only on the page the lookup opened when its address names one (DiveChek's `/divechek`), a student's email only into a box that searches or says it is the student's, never on a sign-in, sign-up, account or profile address (`SIGN_IN_PATH` in `protocol.js`) or a page with a password box or an email box that does not search, and presses only the search's own button (Search, Find, Look up, Check, Chek, Verify, or DiveChek's "Run Report"), never a reset and never a bare submit. A box or button inside a hidden block is not on the page. On CMAS's portal, which has a "Search by code" and a "Manual Search", it presses the first search button after the boxes it filled, in the nearest block around them: the code's for a card number, Manual Search for names and birth date, never a date picker's toggle.
- `background.js`: opens the page in a background tab, runs `fill.js`, reads the answer once three reads a second apart agree, closes the tab. Every lookup is filled and read only on its own site (`origins`, or its address's host). For a signed-in page it answers `signed_out` when PADI shows its sign-in or sends the tab to a host outside the spec's `origins`, before the search and again once the answer settles (`pageAsksToSignIn` in `fill.js`), and hands back only the lines about the diver or student searched for: for a student, the lines carrying their email, their name line above, and the course, status and date lines under it, up to six from the name line, never a line with another address or the one just above it (unless it is a status alone), or only the lines saying why; for a diver, each line naming them (or a name split over two adjacent labelled lines, "First name: Lena" over "Last name: Ortiz", either order, Spanish labels too, labelled lines paired top to bottom so one record's last name never pairs with the next record's first) and the four under it (`RECORD_LINES` in `src/lib/agency-check.ts`), or, when none does, only the lines saying why, at most ten.
  A check that ends short of a page's text on the lookup's own site says why with a fixed reason: `captcha` (a captcha box on the lookup's own form, where nothing is typed, or on an answer that neither names the diver nor finds nobody, whose text is not handed back), `page_changed` (a form, but no box or button where the lookup expects one), `timeout` (no box at all by the deadline: a page with no form yet is waited for, never read as changed) or `fill_failed`, with the page's shape beside it. It answers `hello` with its version and the agencies it checks, and the two requests of Settings' "Try the checks": `dry-run` (with `hostAccess`, whether Chrome lets it on that agency's site) and `padi-session` (`no_access` when Chrome keeps it off PADI's hosts).
- `shape.js`: `describePageShape`, the page-shape report: the path without its query string, title, top headings, each box's tag, type and label words, buttons' words, counts, password and captcha flags (a captcha frame that has drawn its box, never an empty widget or reCAPTCHA's invisible badge), every word cut to `PAGE_SHAPE_WORDS` and the diver's names always "_". Never a value, a cell or a line of the page.
- `sample.html` and `sample.js`: "Try the checks"' dry run. A form shaped by one agency's `fields`, filled by `fill.js` with a made-up diver; the form stops the submit and the page tells the service worker what was found, typed and pressed. CMAS's holds both its searches, each with its own button, and is tried by code and by names and birth date. No agency is opened. PADI has none.
- `icons/`: the 16, 48 and 128 px icons the manifest names (`icons`); the stores ask for the 128.
- `bridge.js`: on DiveDay's pages, sets the `data-diveday-cert-check` marker and carries messages.

`src/lib/cert-check-extension.test.ts`, `src/lib/cert-check-extension-fill.test.ts` and `src/lib/cert-check-extension-excerpt.test.ts` test this folder, and `e2e/agency-check-extension.spec.ts` installs it in a real Chromium against stand-in agency pages: `pnpm e2e:run e2e/agency-check-extension.spec.ts --reporter=line` after `pnpm e2e:build`, with the full Chromium (`pnpm exec playwright install chromium`; the headless shell cannot load an extension).

## Try it locally

1. Open `chrome://extensions` (or `edge://extensions`) and turn on Developer mode.
2. To try it against `pnpm dev`, add `"http://localhost/shop/*"` to the content script's `matches` in `manifest.json`, and leave it out of anything you publish. Chrome ignores the port in a match pattern, so a published localhost pattern would let any local web app use the extension.
3. Choose "Load unpacked" and pick this folder.
4. Open a diver's record with a pending level card from one of the six agencies. "Check with <agency>" is now a button. A PADI card needs the diver's birth date on file and the shop's "PADI checks (beta)" switch on.

Settings, Bookings & waivers, "Certification checks", says whether this browser has it and which version, and its "Try the checks" runs the extension on its own sample pages, asks Chrome whether the extension may go on each agency's site (Extensions, DiveDay certification check, Details, Site access), reads whether a PADI Pros' Site tab is signed in, and gives a report to copy into an email to DiveDay. Run it first, before a real check.

## Test the PADI eLearning check

The PADI page is a best guess (#2259). To test it for real:

1. Load the extension as above and sign in to the PADI Pros' Site in the same browser.
2. Open a PADI course session with learning materials, and a student whose eLearning you know is finished. Open their row's details and press "Check eLearning with PADI".
3. If it answers "Couldn't read PADI's page" or "PADI's page has changed", the `agency_check.page_shape` log line for it holds the page's boxes and buttons; open `https://pro.padi.com/` yourself, find where a student's eLearning is searched, and correct `ELEARNING.padi` in `agencies.js` (the page address) and, if the search box is not found, `PATTERNS.email` in `fill.js`.
4. If it reads the page but gets the answer wrong, copy the page's text into a new case in `src/lib/elearning-check.test.ts` and fix `judgeElearningPage`.

## Test DiveChek against the real page

The DiveChek page is a best guess, like the eLearning page (#2259), and the same sitting should try both. Before relying on it, someone should also read the PADI Pros' Site terms (H-121). Turn on "PADI checks (beta)" in the shop's Settings first.

1. Load the extension as above. Do not sign in to PADI yet.
2. Open a diver's record with a pending PADI level card and a birth date, and press "Check with PADI". It should answer "Sign in to the PADI Pros’ Site first, then check again." If it says "Couldn't read PADI's page" instead, note the address PADI sent the tab to (open DiveChek yourself while signed out) and add its path to `SIGN_IN_PATH` in `protocol.js`, the one copy both `background.js` and `fill.js` read.
3. Sign in to the PADI Pros' Site in the same browser. Find DiveChek yourself and note its address and its search boxes. Note the host at each step too: the link a staffer sees and the check both open `pro.padi.com` (`AGENCY_VERIFICATION_PAGES.padi` and `AGENCIES.padi`), and the extension also reads `pros.padi.com` (`origins`). If PADI sends the tab to a third host, add it to `PADI_ORIGINS` in `agencies.js` and to the manifest's host permissions.
4. Press "Check with PADI" on a diver whose PADI card you know. If it answers "Couldn't read PADI's page", correct `AGENCIES.padi.url` in `agencies.js` and `checkUrl` in `src/lib/agency-verification.ts` (the two must match, and a test holds them together). If the boxes are not found, check that their labels name first name, last name and birth date and that the search's own button says Search, Find, Check, Verify or Run Report, and adjust `PATTERNS` or `BUTTON_SEARCH` in `fill.js`. If the birth date lands in the wrong order, change `dateFormat`; if DiveChek *shows* birth dates day first, change `dates` for `padi` in `AGENCY_CHECKS` (`src/lib/agency-check.ts`).
5. If it reads the page but gets the answer wrong, copy the page's text (only the diver's lines) into a new case in the "judgeAgencyPage on PADI DiveChek" block of `src/lib/agency-check.test.ts` and fix `LEVEL_WORDING.padi` or the rule. Check what a diver with several certifications looks like (one row per card, or one name over several), whether the card number shows on each row, and whether a Junior card shows as "Junior Open Water Diver" or "Jr. Open Water Diver".
6. Try a diver with a common name: a page listing several divers must answer "PADI lists more than one diver by this name." and certify nothing.

## Publish

1. Bump `version` in `manifest.json` and `VERSION` in `protocol.js` together. A test holds them equal. When the fix must reach every browser before it checks again, raise `MIN_EXTENSION_VERSION` in `src/lib/cert-check-extension.ts` to it, and the stand-in versions the e2e specs announce.
2. Zip this folder's contents, leaving out this README.
3. Upload to the Chrome Web Store developer dashboard. The listing needs a privacy policy URL and a reason for each host permission: "Fills in this agency's public certification lookup form when the user asks, and reads the answer."
4. Edge Add-ons accepts the same zip.
5. Put the listing's address in `EXTENSION_STORE_URL` (`src/lib/cert-check-extension.ts`). Settings then shows "Add to Chrome".
