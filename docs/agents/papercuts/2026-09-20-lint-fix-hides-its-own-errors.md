Project: tooling / session habits
Symptom: CI's Lint job went red twice on one branch while every local check was green. `pnpm lint:fix` is `biome check --write`, which applies only the *safe* fixes — `noUnusedImports` and `noUnusedVariables` are classed unsafe, so it leaves them as errors and reports them on stdout. Using it as the pre-commit check and redirecting its output (`pnpm lint:fix >/dev/null 2>&1; pnpm typecheck`) turns both into silence: typecheck passes, the tree looks clean, and CI is the first thing that says otherwise. Both instances were the same shape — a refactor that stopped reading an import or a destructured field, exactly what that rule exists for.
Fix: `pnpm lint:fix` formats; `pnpm lint` is the check, and it is the one whose exit code matters before a commit. `pnpm exec biome check --max-diagnostics=200 .` is the form that shows every hit — the default diagnostic cap hides the errors behind ~30 pre-existing `noTemplateCurlyInString` warnings in `scripts/*.test.mjs`, so a truncated run can print the warnings and drop the three errors that actually fail the job.
