Date: 2026-10-03
Project: tooling / agent layer
Symptom: Main's 4edd157 ("Matt Pocock skills") vendored 37 skills under `.agents/skills/` and linked them into `.claude/skills/`, which made `.claude/skills/triage` a symlink. `scripts/check-agents.mjs` listed skills with `readdir(..., { withFileTypes: true })` filtered on `isDirectory()`, which is false for a symlink, so the index row for `triage` read as stale and Repository safeguards went red on every open PR at once. The same four-line fix ("check:agents: a skill linked in from .agents/skills exists") then had to be committed four times, once per layer of an open stack (b995d3a, 3715231, 269f8ca, 8f5bef6), because each layer runs the whole gate. `scripts/check-context-budget.mjs` and `scripts/agent-health.mjs` had the same blind spot and silently under-counted the always-loaded skill descriptions by about 500 words until 2026-10-07.
Fix: Anything that walks `.claude/skills/` follows links: `listDirs` in `scripts/check-context-budget.mjs` (`isSymbolicLink()` plus `stat`), or `existsSync(<dir>/SKILL.md)` as check-agents does. Adding or removing an imported skill touches three places together: the link in `.claude/skills/`, the source in `.agents/skills/`, and its `skills-lock.json` entry. Land a change like that on `main` before stacking on it, so a fix to it is one commit rather than one per layer.
