# 20261008-cert-check-extension — Check a card on the agency's own page from the staffer's browser

- **Status:** Accepted
- **Date:** 2026-10-08

## Context

No agency offers a certification API ([H-10](../../product/human-decisions/README.md)), so [20260721-manual-certification](20260721-manual-certification.md) made certifying a manual lookup, and a card waiting for one carries a link to its agency's public lookup page (`src/lib/agency-verification.ts`). The staffer still opens the page, types the diver in, reads the answer and comes back to tap **Mark certified**. DiveDay's servers cannot do that lookup for them: the pages are the agencies', meant for a person, and PADI's sits behind the shop's own member sign-in. The staffer's browser can. Aaron asked for a browser extension that does the lookup from there, shows only when installed, falls back to the link, and is offered from Settings ([H-105](../../product/human-decisions/README.md)).

## Decision

**SSI amendment (2026-10-26):** SSI's lookup requires the user to attest ownership or
authorization. Extension 1.6.0 opens SSI in the foreground and waits up to two minutes for the staffer
to reveal the form by accepting SSI's terms, then fills the known name and birth date together only
when all known fields are visible and no existing values conflict. Editing a field stops the fill;
the staffer reviews the terms and submits. The extension never accepts the attestation, submits,
reads the result or certifies from SSI, and Check all excludes SSI. Other agencies retain the
automatic check below. The app requires 1.6.0 for SSI manual fill; older supported copies still
check other agencies and SSI tells the staffer to update.

- **A Manifest V3 extension, `extension/` at the repo root**, plain scripts with no build step and no dependencies. Chrome and Edge first. It holds host permissions for exactly the agencies it checks (SSI, NAUI, SDI, GUE, CMAS, and the PADI Pros' Site on both its hosts, `pro.padi.com` and `pros.padi.com`). Its content script runs only on DiveDay's staff pages (`https://dive.day/shop/*`), and the service worker answers only the top frame of one. A localhost pattern is for local testing and is never published, because Chrome ignores the port in a match pattern.
- **The extension carries words and decides nothing.** On a request it opens the agency's lookup page in a background tab, fills the form by what each box says about itself (`extension/fill.js`), waits for the answer to settle, hands the page's text back and closes the tab. If a box the lookup needs is missing it submits nothing.
- **The verdict is the server's.** `agencyCheckAction` reloads the card and the diver from the database and `judgeAgencyPage` (`src/lib/agency-check.ts`) reads the text as records: a line with the diver's first and last names in order or as "Last, First" (or, amended 2026-10-15, two adjacent lines each one name label and the diver's own name with a few middle names or particles at most, "First name: Lena" over "Last name: Ortiz", labeled lines being paired top to bottom once so one record's family line never pairs with the next record's given line, and a pair beside a stray labeled name line refused), and the few lines after it up to the next line naming them again or a line that starts with the agency's own page furniture (`PAGE_FURNITURE_WORDS`: SDI's "Don't see your certification?" note, GUE's footer) or is a search control alone (`SEARCH_CONTROL_LINES`: "Manual Search", "Back to search"), whose words are never the diver's; a limiting word on the furniture's own line is still read. A labeled pair's record ends at the first line that is not a date, a rating's or card's words, a number or a record's own label, and is no record at all unless a rating's line carries a date or number: the search form echoed back under its labels, with a menu's level below, is not a result, though on DiveChek its birth date still counts toward several divers. A bare "not found" is not a no-record answer: a 404 or a moved form reads as `unreadable`. "Jr." straight after the diver's last name on the name line is a name suffix, unless a level follows it. A match's review note keeps only the diver's name, the certifications' words, dates, numbers and a record's own labels, on every line, so a neighbor's name inside the record's window is never kept. A record matches only when it also carries the birth date or card number the lookup was typed with (so a namesake is not certified, and the next row's level is not read as theirs), states the claimed level in that agency's own wording, and says nothing limiting (junior, referral, student, online, restricted, a try-dive, and on a public lookup a trainer's title). A birth date written all in numbers whose day and month are both 12 or under is read in the agency's own order only (`dates` in `AGENCY_CHECKS`), so a transposed date is another diver's. Short of a match the answer says which: `namesake` (someone by this name, never with this birth date or number; their words are never shown), `limited_card`, `level_unconfirmed`, `no_record`, `unreadable`. Divemaster and instructor cards are never checked (`isAgencyCheckableLevel`) and keep their link, and a TDI card is not checked either, its recreational ratings being SDI's. A higher rating's wording contains the lower one's, so it matches the lower claim; a lower never matches a higher.
- **A match certifies the card with no second tap** (H-105), through the ordinary review: `status = verified`, the staffer whose browser ran the check as `reviewedByPersonId`, the agency's matching words as `reviewNote`, and `certifications.agency_checked_at` stamped. That stamp means **the staffer's browser reported a match**, not that the agency signed anything: it attests what Mark certified attests, with the same permission (see Consequences). A match on a pending card answers `certified`, on an imported card `confirmed`, and the staffer is told which. The check's own Undo takes all of it back, and takes back only a review a check made, on that diver. Anything short of a match writes nothing and puts the link back beside what the page showed.
- **A departure's "Check all"** (`runAgencyCheckQueue`, `src/lib/agency-check-queue.ts`) is only the one-card check, card after card, one in flight, with a pause between. One unreadable result is that diver's and is skipped; two unreadable results or unanswered requests in a row stop the run, and a signed-out agency stops it at once. The staffer can stop it, a re-run skips what the page already settled, and the page repaints once when the run ends. Each card keeps its own Undo, and there is none for the departure.
- **The app finds the extension by a marker**, `data-diveday-cert-check` on `<html>`, and talks to it with `window.postMessage`, which every browser's extensions share. `src/lib/cert-check-extension.ts` and `extension/protocol.js` are the two copies of the wire format, held together by a test.
- **Scope.** Level cards that are pending or imported-awaiting-confirm. An unsighted self-declaration keeps the sighting form: its agency is often unstated and its number is the diver's typing. Specialty and nitrox cards keep the link; a match may offer the page's other cards as pending ones, which its Undo takes back (layer 3, below). PADI is checked on DiveChek since [H-121](../../product/human-decisions/README.md) (below).
- **Settings says whether this browser has it**, in Bookings, with an "Add to Chrome" link once the Chrome Web Store listing exists (`EXTENSION_STORE_URL`).

## PADI eLearning (H-106)

- **What it checks.** A course student's PADI eLearning, from the session's roster, beside the materials tick of [20261008-course-learning-materials](20261008-course-learning-materials.md). Only on a PADI course with materials, for a seat not yet ticked whose student has an email and a first and last name (`elearningCheckQuery`, `src/lib/elearning-check.ts`).
- **Where it looks.** The PADI Pros' Site (`https://pro.padi.com/`, `ELEARNING` in `extension/agencies.js`), searched by the student's email, in the staffer's own signed-in browser. The extension types the email only into a box that searches (by its type, a search landmark, or its words), never on a page with a visible password box or a sign-in, sign-up or account address, so the student's details never go into a login or invite form. It hands back only the student's own lines (`excerptAround`): each line carrying their email (an address read as the server reads one, so brackets and punctuation around it are not part of it), their name line just above it, and the lines under it that are a course, a status or a date, never more than six lines from the name line (the record the server reads from there), never a line with none of those (the next student's name), never a line carrying any other address, never past one, and never the line just above one unless it is a status alone ("Complete"), which is this student's; when no line carries the email, only the lines saying why (no result, a count, a sign-in), at most ten, none with an address (amended 2026-10-15 on security review; it was eight lines either side, or the page's first forty). The rest of a signed-in PADI page is other students'. The address, the search box and the wording are a **best guess** (#2259): nobody has seen the real page yet.
- **The verdict is the server's**, as for cards. `elearningCheckAction` reloads the seat, student and course from the database, scoped by shop, and `judgeElearningPage` finds one record carrying the student's name and email, then a line naming this course (every title word, and no word of a different course, so Advanced, Junior or Tec never reads as the course they contain), then its status: complete or 100%, with nothing saying in progress, started, due, a lower percent or fewer parts than all. A status is read from the course line, or the line under it when that line is a status alone. A record ends at a second email address, so neither the next student's row nor a sibling's on a shared family email is read as this student's.
- **A finished course ticks the materials with no second tap**, through `recordCourseMaterialsDone`, stamped with the staffer whose browser ran the check. A seat already ticked is left exactly as it was, and the check's Undo takes back only a tick still stamped with the staffer who pressed it. Anything short of finished writes nothing and says what PADI's page showed. No new column: the toast carries PADI's words.

## PADI DiveChek (H-121)

- **A per-shop switch, off by default** (amended 2026-10-15). Both PADI checks, DiveChek and eLearning, wait for the shop's own "PADI checks (beta)" in Settings, Features (`shops.padi_checks_enabled`, an optional feature of [20261005-optional-shop-features](20261005-optional-shop-features.md), the second after "Our year" to default off). The check runs in a staffer's browser under the shop's own PADI membership, whose license is the member's and not transferable, and nobody has yet tried it on the real page or read the Pros' Site terms, so the shop opts in, not DiveDay for it. Off, a PADI card keeps its "(member sign-in)" link only: no "Check with PADI" on the diver record, a departure's Divers tab or Today, none counted in "Check all", no "Check eLearning with PADI" on a course roster, and the server refuses a check posted anyway (`agencyCheckOffered`, `src/lib/agency-check.ts`, read by every query that offers or accepts a check). An owner or manager turns it on; off, a staffer with the extension reads that PADI checks are off and who can turn them on, beside the link and beside a course roster's materials tick. A course's agency is free text, so "PADI" in any case is PADI (`foldText`). The seeded demo has it on. Two exits, confirmed by Aaron Buxbaum on 2026-10-15 (H-121): "beta" comes off after a real match, no record, several-divers page, signed-out page, Junior or "Jr." card, PADI Scuba Diver card and a non-US Pro's date format have each been seen; the default turns on only after the Pros' Site terms are pasted into H-121 or PADI answers in writing.

- **What it checks.** A pending PADI level card, from the same places as every agency (the diver record, a departure's Divers tab, Today, a departure's "Check all"), when the diver has a first and last name and a birth date on file: DiveChek is searched by name and birth date (`AGENCY_CHECKS.padi`, `src/lib/agency-check.ts`). The button says "Check with PADI"; the fallback link keeps "(member sign-in)".
- **Where it looks.** DiveChek on the PADI Pros' Site, the host the eLearning check reads (`AGENCIES.padi` in `extension/agencies.js`, `checkUrl` in `src/lib/agency-verification.ts`; the staffer's link is the same host's front door, so one sign-in serves the link, the check and eLearning), in the staffer's own signed-in browser. DiveDay never holds a PADI sign-in. The host is `pro.padi.com`, where PADI's own sign-in page, 2024 member brochure and member FAQ send pros (amended 2026-10-15; it was `pros.padi.com`, which also answers). The extension may read both (`origins`), so a tab PADI sends from one to the other is still the signed-in site and not a `signed_out`. The path, the form and PADI's wording are a **best guess** to be tried with #2259; PADI's published instructions name DiveChek's button "Run Report", which the filler presses.
- **A signed-in page is held tighter** (`signIn` on the agency's spec). The filler finds every box and the button before typing anything. It types only into boxes that search: a search box, a search landmark, the box's own words, or a form's search button when every box in that form is one this lookup fills (a profile form with Search beside Save, or a Verify under a Phone box, is neither; a reset is never the search). A student's email goes only into a box that searches or says it is the student's, never a report's "Email a copy to". It types only on the page the lookup opened when its address names one (DiveChek's `/divechek`, trailing slash and case aside, on either PADI host). It refuses a sign-in, sign-up, account or profile address (`SIGN_IN_PATH`, spelled once in `extension/protocol.js`), any page with a visible password box or an email box that does not search, and presses only the search's own button (Search, Find, Look up, Check, Chek, Verify or Run Report, as whole words), never another of the page's, never a reset and never a bare submit of the form. A box or button inside a hidden block is not on the page. The service worker answers `signed_out`, a fixed code, when PADI shows its sign-in (a password box, a sign-in address, or another host it may not read), before the search and again once the answer settles, so a session that lapses between the form and its answer never reads as a result. Every lookup, public or signed in, is filled and read only on its own site (`origins`, or its address's host): a public lookup sent to PADI's Pros' Site is refused, and any page on a signed-in host hands back only the diver's lines. A signed-in page hands back only the lines naming the diver (a name split over two adjacent labelled lines, "First name: Lena" over "Last name: Ortiz" in either order, counts as one, read exactly as the judge reads one, so a second diver laid out that way still reaches the judge) and the lines under each as far as the server reads that record (`DIVECHEK_RECORD`, the judge's own words, copied into `extension/protocol.js` and held equal by a test), so a neighbour's name or birth date under the diver's record never leaves the browser, with a gap line between lines that were not neighbors, so no record or labelled pair runs across lines the page kept apart; every other line comes back only as its words saying why or how many (no result, "2 divers found", a sign-in), each once (amended 2026-10-15 on domain review: it was the four lines under each name, and whole lines saying why).
- **The verdict is the server's, narrower than for a public page.** `judgeAgencyPage` certifies only **one diver**: DiveChek may list a row per certification, so records naming the diver are grouped by the birth date each carries, and rows sharing the typed birth date are one diver's cards. Two birth dates under the name, or a line saying "2 divers" or more, answer `several_records`; "3 results" or "3 records" does not, being possibly one diver's cards. A record ends at the first line that could be someone else's: a line naming the diver again, a line with neither a digit nor a rating's words (another diver's bare name), or a line with a date that is not the birth date and no rating's words (another diver's name and birth date), and never more than four lines under the name. Its birth date sits on the name line or the line under it, before the level; when the card has a number on file the record carries it too, though the number is never typed into DiveChek. PADI's own words for the level match (Open Water Diver, Advanced Open Water Diver, Rescue Diver; "Scuba Diver" never does). An instructor named on the row is the trainer who certified the card, not a limit. **"Junior <level>"** is the level for a diver 15 or older on the day of the check, read from the clock on the earliest calendar day anywhere, because PADI's junior ratings become the full rating at 15; under 15 it answers `junior_under_15` ("PADI shows a Junior card. Under 15, record it by hand."), and a bare "Junior" is a limit at any age. PADI's short "Jr." reads as "Junior". A namesake with another birth date answers `namesake` and none of their words come back. After a match, the other cards offered (layer 3) come only from records carrying the checked card's PADI number when it has one: a same-name, same-birth-date record under another number may be another diver's.
- **Signed out.** The staffer reads "Sign in to the PADI Pros' Site first, then check again", on DiveChek and on the eLearning check alike, never "Couldn't read PADI's page", and nothing is sent to the server. A "Check all" stops on it at once, naming the diver it stopped at, because it is the agency's state and not one diver's: every PADI card after it would meet the same sign-in.
- **Terms.** DiveChek is a PADI member benefit, and PADI may read an extension filling its search as automated use. No published PADI clause found forbids it, but the Pros' Site's own terms sit behind the sign-in and have not been read. H-121 records that this was weighed, the call to build it pending a read of those terms and a real-page test, and the switch that holds it off by default until then.

- **Amended 2026-10-23 (Aaron Buxbaum, H-121): the switch starts on.** `padi_checks_enabled` now
  defaults true for a new shop, and the seeded shops no longer set it. This replaces the exit
  above that held the default off until the Pros' Site terms were read or PADI answered: Aaron

## Other cards on the agency's page (layer 3)

- **What it offers.** After a match the same page often lists the diver's other ratings. `agencyListedCards` (`src/lib/agency-check.ts`) reads them, and the staffer sees "PADI also shows these certifications. Add them? Each waits for Mark certified." with one tick per certification, all ticked. Nitrox and the specialties a site or trip can require (`dive_specialty`), never levels: a level card's number is the agency's number for the diver, unique per agency at a shop, so a second level card cannot sit beside the one just checked, and a higher rating stays the staffer's to record.
- **Only this diver's lines.** Offers come only after a `match`, and only from the records the judge itself read as this diver's (the same window, name, birth date and card number rules), never a limited or junior one. A record is read only as far as every line is explained: the name line, the birth date, and lines made of a certification's name in that agency's words, dates, numbers, the card number on file and a few words such as "issued" (`RECORD_LINE_WORDS`). A recreational certification DiveDay holds no kind for, in that agency's words (`PASS_OVER_WORDING`: Perfect Buoyancy, Adventure Diver, Underwater Navigator, Skin Diver and the like), explains its line and offers nothing, so the cards under it are still read. The first line with any other word ends the record, so a neighbour's bare name, a neighbour's name beside a rating, another birth date on a line naming no certification, "Tec Deep Diver" or "Deep Diver Specialty Instructor" stops the reading there. On DiveChek a row may name the instructor after the certification's date, so a line is read up to the trainer's word; a trainer's word straight after a certification's name is a professional rating and ends the record. A certification's own name is never a limit: SSI's "Night & Limited Visibility Diving" does not make the record a limited one.
- **A closed table per agency** (`LISTED_CARD_WORDING`): PADI's "Enriched Air Diver" (and "Deep Diver Specialty", the name with PADI's trailing word), SSI's "Enriched Air Nitrox" and "Night & Limited Visibility Diving", NAUI's "Wreck Diver (External Survey)" but never "Wreck Penetration", SDI's "Computer Nitrox Diver", and so on. Wording that is not in it is ignored, not guessed. GUE issues no nitrox card: its Recreational Diver 1 bundles enriched air, so that line offers nitrox (`BUNDLED_NITROX`), on the level card's own number, as the glossary's **Bundled nitrox** says. A kind the diver already has on file, in any state and from any agency, is never offered, except a diver's own unsighted nitrox self-declaration: a join form's tick names no agency and no number, so the card the page lists replaces it, and adding it archives the claim, as any card the shop holds outranks the diver's word.
- **The number, per agency** (`AGENCY_CHECKS[agency].numbersTheDiver`). PADI, SSI, NAUI and GUE give the diver one number every card carries, so a listed card borrows the checked card's number and its confirm is the ordinary one-tap **Mark certified**. SDI and CMAS number each card: a listed card takes the number printed on its own line when the line lists that one card and shows exactly one number that is neither a date nor the checked card's; otherwise it is filed with no number, and its confirm is the card sighting, which asks for the agency and number off the card (`needsCardSighting`). The schema allows a numberless row only while it is pending, as it does a self-declaration and a shop-issued card. A confirmed listed card at those two agencies has no status-flip Undo: its number may have been typed off the card, and a revert cannot tell (`unreviewedCardState`).
- **Pending, stamped, with the agency's words.** Ticked certifications land `pending`, the agency's words (this diver's record lines) as the review note, stamped with the level card whose check listed them (`listed_from_certification_id` on `nitrox_certifications` and `specialty_certifications`). They are never certified by the check: nitrox authorizes a fill and a specialty opens a site. The stamp is the card's provenance: the row says "Listed on PADI's page." by it, before and after the confirm, so a later reader can tell the agency's words from a staffer's. A confirm that brings no note keeps the agency's words, and so does the Undo of that confirm, because the note was never the review's. The record's name line is cut to the diver's name as matched, the certifications' names, dates and numbers, so an instructor or dive centre named on it is never kept; a match's own review note is cut the same way.
- **The check's Undo takes them back.** Undoing the check (`undoAgencyCheck`) puts the level card back and, in the same transaction, archives every card its page listed that is still pending. A listed card a staffer has since certified is theirs and stays. A self-declaration a listed nitrox card retired stays retired: the shop can record the diver's word again, and a claim that resurfaced on its own would read as something somebody said twice.
- **The server believes the page text and the ticks, nothing else.** `addAgencyListedCardsAction` reads the matched card again (this shop, this diver, certified by an agency check, so not a card certified by hand or one whose check was undone), judges the posted page again and requires a match, derives the offer again, and files only if every tick names a kind that offer holds. A forged tick files nothing; a repeated or replayed one files nothing while the card it filed is on file, and once that card is deleted a replay of the same page and ticks offers it again, as the check itself would. The write locks the diver, reads the matched card again under a share lock (so an Undo between the offer and the tick either waits for it, and then archives what it filed, or leaves nothing to file), and re-reads what is on file, so two posts of one offer file it once.
- **Where it shows.** Under the certified card on the diver record. Under the diver's row on a departure's Divers tab, and after a "Check all" has finished, never during it: the run is not interrupted, and each row offers its own afterwards. On Today under the Needs you list, naming the diver with a link to their record, because the row leaves with the card it was about. The page text stays in the staffer's browser while the offer waits for a tick, and is dropped once the cards are filed or the page is left.
- **A pending nitrox or specialty card has its own button** (amended 2026-10-15, issue #2592, Aaron: yes). `nitrox_certifications` and `specialty_certifications` carry a nullable `agency_checked_at`, the twin of the level card's, so the check's Undo can tell an agency-checked review from a staffer's and put the card back (`reverseNitroxReview`, `reverseSpecialtyReview`; the one-tap Undo refuses an agency-checked card with `agency_checked`). The column is in the export bundle. `judgeAgencyListedCard` (`src/lib/agency-check.ts`) is the judge: the same page and diver rules as the level check, then a line of the diver's own record in the closed per-agency wording for the card's kind (`LISTED_CARD_WORDING`), read by the same line scan as the offer (`listedOnRecord`), and the card's own number on that record. It never certifies from a level card's match alone, and an agency whose table lists no such kind answers `level_unconfirmed` and writes nothing. A card that needs the card in hand is not checkable (`needsCardSighting`: a diver's own tick, a card this shop's instructor issued, a card an earlier check listed with no number), nor one with no number of its own; the list and the action share one rule (`checkableListedQuery`, `src/db/agency-check.ts`). `agencyCheckAction` takes the table in `cardType` (absent for a level card); the buttons read "Check Nitrox with SSI", so a diver's two cards at one agency never wear the same words. It is offered on the diver record and a departure's Divers tab (and its "Check all"), not on Today's "certification pending" row, which names a level card. A match offers no further cards and files none: the page's other cards are a level card's to offer.
- **Known gap.** The real pages are still to be seen (#2259 for PADI); the wording, pass-over and per-card number rules are the agencies' published names, not their pages.

## When a check cannot finish, which copy is installed, and a trial run (round 3)

Amended 2026-10-15, so the first real session (#2259) teaches the most and a staffer can run it alone.

- **A page-shape report, never the page.** When a check ends short of the page's text on the lookup's own site (its form could not be filled, its answer never settled, or a captcha stands in the way), the extension hands back the page's **shape** (`describePageShape`, `extension/shape.js`) beside a fixed reason: the path without its query string, the title, the top three heading levels, each box's tag, type and label words, each button's words, counts of forms and frames, and whether a password box or a captcha is there. Every text is cut to a fixed vocabulary of form words (`PAGE_SHAPE_WORDS`, in `extension/protocol.js` and `src/lib/page-shape.ts`, held equal by a test); every other word becomes "_", a digit is never a word, and the diver's own names are always "_". So no name, date or number on the page can leave it: the report can say "first name", "date of birth", "run report", never who. No value, table cell, paragraph or result row is read. A lookup sent to another site is not read at all, not even its shape. Capped at 4 KB.
- **The server logs it, and trusts none of it.** The browser posts the agency, the reason, the extension's version and the shape to `reportAgencyCheckPageAction`, which parses it again (`parsePageShape`: closed keys, closed types, bounded lists, every word in the vocabulary, or nothing is logged) and writes one structured line, `agency_check.page_shape`, with the shop's id and no person. It is never rendered. A signed-out PADI check sends nothing: that is the staffer's sign-in, not the page. At most 30 a staffer and 120 a shop an hour are logged (`RATE_LIMITS.agencyCheckReportByPerson`, `agencyCheckReportByShop`); past that a report is dropped unread. The report is fire and forget and may never arrive, so no sentence says DiveDay was told.
- **Two more fixed reasons, each with its sentence.** `captcha`: a captcha that has drawn its box (a captcha frame on the page, never an empty widget, a hidden frame or reCAPTCHA's invisible badge) on the lookup's own form, found by the filler before anything is typed (`missing: ["captcha"]`); a captcha elsewhere on the page, on a newsletter's form, stops nothing. A page with no box at all (a challenge in front of it) is waited for to the deadline, and is `captcha` then if a captcha is on it. On the settled answer, a captcha anywhere withholds the text only when the text neither names the diver nor says it found nobody. "SSI is asking if you're human. Check on its page." `page_changed`: the lookup page loaded on its own site, has a box to type into, and the filler found no box or button where it expects one after five tries; a page with no box yet is never changed, only `timeout` at the deadline. "SSI's page has changed. Check on its page." `unsupported` (this copy does not check the agency) now has its own sentence too: "This copy of the extension doesn't check SSI. Update it." Each puts the agency's link in the button's place, on the diver record as on a row, and writes nothing. To a "Check all" each is the agency's state, not one diver's: that agency's other cards are left unsent (`leavesAgencyCards`), the other agencies' go on, and the run's last line names the agency ("Left SSI's other certifications for you"). `fill_failed` remains for a page the extension could not script or a lookup sent off its site.
- **A minimum version.** `MIN_EXTENSION_VERSION` (1.5.0) is the oldest copy the app talks to; an older marker is treated as no extension, so every check falls back to the agency's link, and Settings says "Update the extension: this browser has 1.2.0, DiveDay needs 1.5.0." A fix shipped after a pilot installed the extension reaches them, or they are told it has not. The extension answers a `hello` with its version and the agencies it checks (`agencies`, `elearning`); "Try the checks" reads it, and runs a sample only for an agency that copy lists.
- **Try the checks**, Settings, Card checks (owners and managers). One disclosure on the row (a page of its own until #2817), one button, four steps, all in the staffer's browser and none against an agency: the extension is here and current; a **dry run** for each public agency, in which the service worker opens `sample.html` (a page the extension carries) in a background tab, the real `fill.js` fills a form shaped by that agency's `fields` with a made-up diver, the form stops the submit, and the page reports whether every box was found, typed as the agency wants and the search pressed (CMAS's sample holds both its searches, each with its own button, and is tried by code and by names and birth date); PADI has no dry run, because its filler types only on DiveChek's own address; and whether an open PADI Pros' Site tab is signed in, read with `pageAsksToSignIn` alone (no tab opened, nothing typed or searched, one word back). Each dry run, and the PADI step, also asks Chrome whether the extension may go on the agency's own hosts (`chrome.permissions.contains`, both PADI hosts for PADI): a person can withhold a host in the extension's site access, and a sample that passes on its own page then still fails, with the step that turns it back on (the PADI step says "Not allowed on PADI's site"). A failed sample says to send the report; the PADI step says when the shop's PADI switch is off. With no answer to `hello`, nothing more is sent. It ends in a session report to copy into an email to DiveDay's support address: versions, each step's outcome and host access, each sample's page shape, the browser's user agent, and nothing about a diver, a staffer or the shop.
- **Not built in this round:** a "Copy page report" button on a failed row (the log line and the try page's report carry the same shape), the prefilled visible tab for a captcha (round 2, idea 1), and the extension version in a check's review note.

## Alternatives considered

- **A server-side scraper.** Rejected: it would be DiveDay's servers hitting the agencies' pages at volume from one address, which is what H-10's "never fetches" stance was against, and it could never use a shop's PADI sign-in.
- **The extension judging the page itself.** Rejected: an extension update ships through store review, so the rule that certifies a card would be the slowest thing to fix and untestable in CI. Words in, verdict on the server, under tests.
- **A staffer's confirm tap on every match.** Aaron chose auto (H-105). The narrow match rule and Undo are what make that safe.
- **Chrome's `externally_connectable`.** Neater, but Chromium only; `postMessage` works in Firefox and Safari too.

## Consequences

- An agency that redesigns its page breaks that agency's check until the extension ships a fix. The check then answers that the page has changed, DiveDay's log holds its shape, and the link is still there. A staffer whose copy is older than the minimum gets the link until they update. CI cannot test against the live pages; the filler and the judge are tested on stand-ins.
- A captcha drawn on an agency's lookup form stops that agency's check, and says so ("is asking if you're human"), with the link; nothing is typed.
- Phones never have it: mobile Chrome runs no extensions. It is a front-desk feature.
- "Checked with SSI by <staffer>" is the staffer's attestation that their browser read the agency's page, not proof the agency gave DiveDay: a staffer could post page text by hand, or a script on a DiveDay page could fake the extension's reply. Either reaches no further than Mark certified, with the same permission, and the review names the staffer either way.
- The extension sends the diver's name and what that agency's form asks for to the agency's site, as the staffer did by typing them: a birth date or a card number, both only for CMAS (`agencyCheckQuery`). Only cards still waiting for a check build a lookup.
- Publishing to the Chrome Web Store needs DiveDay's developer account, a privacy policy and the host-permission justifications: a human step.
- The eLearning check types only the student's email into PADI's site, which already holds it for the student it enrolled, and hands back only the student's own lines.
- The DiveChek check sends the diver's name and birth date to PADI's site, as the staffer would by typing them, and reads back only the diver's own lines. A results list with more than one diver by the name is never read as a match, even when one row would have been; a neighboring diver's row inside the excerpt ends the record when it reads as another person's (a bare name, or a name and another birth date), but a neighbor's line that carries a rating's words and no date (a name and a level on one line) still reads as part of the record above it. That is a known gap for the real-page test (#2259) to look for.
- The extension does not know a shop's PADI switch. The app is what holds it off: no button is drawn and the server refuses a page posted for a shop with the switch off. A page could still ask the extension directly; what comes back is refused by the server.
- The answer is read as settled when three reads a second apart agree. A page that draws its result in pieces more than two seconds apart could be read before it finishes; the server then reads fewer of the diver's lines, never another diver's, and the real-page test (#2259) is where to watch for it.
- On CMAS a gap in the portal is not a wrong card: federations are still adding theirs, so "nobody found" there says to ask the federation named on the card.
- Revisit when an agency offers an API, or if one objects to the lookup.
